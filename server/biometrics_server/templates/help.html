How the agent works

Each monitored machine runs its own agent, which follows four steps:

  1. Sensory: it records keystroke timing continuously.
  2. Cognitive: every window of keystrokes is scored by the owner's XGBoost model, and the policy turns the score into a level.
  3. Action: it responds step by step (challenge → alert → critical).
  4. Explainable / human-in-the-loop: it shows the person at the keyboard why it reacted and asks them to re-authenticate.

Reading an incident

Each incident page lists the features that pushed that window toward "not the enrolled user", strongest first. For each one it shows:

  • This window: the feature's value, averaged over the window's keystrokes.
  • Usually: the middle 50% of the user's own training data.
  • Flagged: the value was above or below that range.
  • SHAP: how much the feature moved the decision.

SHAP is measured in log-odds: +1.0 means the feature alone made "someone else" about e1 ≈ 2.7× more likely than the model's average starting point. Contributions add up across features, which is why a value inside the usual range can still appear: it counted in combination with the others.
